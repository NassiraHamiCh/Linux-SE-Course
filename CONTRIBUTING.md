# Guide de contribution

Merci de votre intérêt pour contribuer à ce cours ! 🎉

## Comment contribuer

### 1. Signaler un problème

Si vous trouvez une erreur ou avez une suggestion :

1. Vérifiez que le problème n'a pas déjà été signalé dans les [Issues](../../issues)
2. Créez une nouvelle Issue en décrivant clairement le problème
3. Incluez des exemples si possible

### 2. Proposer des améliorations

Pour proposer du nouveau contenu ou des améliorations :

1. **Fork** ce dépôt
2. Créez une branche : `git checkout -b feature/amelioration`
3. Effectuez vos modifications
4. Testez vos changements (scripts, commandes, etc.)
5. Committez : `git commit -m 'Ajout de nouvelles commandes'`
6. Push : `git push origin feature/amelioration`
7. Ouvrez une **Pull Request**

### 3. Standards de qualité

#### Documentation (Markdown)

- Utilisez des titres clairs et hiérarchisés
- Ajoutez des exemples pratiques
- Incluez des explications détaillées
- Vérifiez l'orthographe

#### Scripts Shell

```bash
#!/bin/bash
# Description du script
# Auteur: Votre nom
# Date: YYYY-MM-DD

# Code bien commenté
# Utilisation d'indentation claire
```

- Ajoutez le shebang `#!/bin/bash`
- Commentez le code
- Testez sur Ubuntu/Debian avant de soumettre
- Gérez les erreurs proprement

#### Exercices

- Fournissez des énoncés clairs
- Incluez des solutions détaillées
- Ajoutez des commentaires explicatifs
- Proposez plusieurs approches si possible

### 4. Types de contributions

Nous acceptons :

✅ Corrections de fautes et coquilles  
✅ Ajout d'exemples et d'exercices  
✅ Amélioration de la documentation  
✅ Création de nouveaux scripts  
✅ Traduction en d'autres langues  
✅ Suggestions d'organisation

### 5. Code de conduite

- Soyez respectueux et constructif
- Acceptez les critiques constructives
- Aidez les autres contributeurs
- Restez professionnel
